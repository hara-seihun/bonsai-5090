# Research export scan and boundaries

- Source-only allowlist: CUDA/C/C++/Lean/Python/shell/build-description text, Markdown and compact numerical JSON/CSV/log/resource receipts. No `.git`, Git bundles, weights/caches, activation/logit/weight-row dumps, binary dictionaries, executable/object/library/cubin files, profiler trace payloads, dependency trees or compiler expansions.
- All `build`, `build-*`, `CMakeFiles`, temporary, vendored/dependency and cache directories were pruned, including generated CMake CUDA compiler-ID source in Dict8 CPU custody. Authoring `build.py` and named build receipts remain source/evidence files, not build trees.
- Original host/account locators and private presentation pointers were sanitized. Original per-file SHA256 remains beside exported SHA256 in `SOURCE-MANIFEST.json`. Numerical values/hashes are not changed to make a claim pass.
- The manager's redacted preliminary whole-tree scan had102 research matches. Every research match was inspected/classified: SHA1 commit named `api`, SHA256 artifact/generated-token bindings, or the `inherited_key_case_passed` boolean test expression. No credential was identified. `PRELIMINARY-SCAN-CLASSIFICATION.json` gives per-path classification; deleted paths remain marked pruned.
- Public-data/scientific variable names such as key, token, API, SHA and source constants are expected. A source/binary hash is an identity receipt, not an authentication credential. No blanket scanner suppression is installed.
- Historical receipts may name omitted original artifacts and sanitized machine paths. They prove only the observations written there, not availability of excluded payloads. `BUILD.md` identifies tests needing excluded real-row/model inputs and the source-only external serving boundary.
- No inference, CUDA runtime initialization, model/cache creation, paid job, source-owner mutation or Git staging/commit/push was done by this export. The root integrator owns the final whole-tree scan and push.
